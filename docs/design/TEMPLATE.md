## Proposal

What are we building? Describe the solution at the level someone needs to implement it. No field listings — those belong in code. Focus on:

- **What changes** — new models, new endpoints, new components (names and purpose, not field-by-field)
- **How it works** — the flow, state transitions, or algorithm in plain language or a diagram
- **What it touches** — which existing models/views/components are modified and how

Keep it short. If a section needs more than ~20 lines, it's too detailed for a design doc — that detail belongs in code comments or the PR description.
